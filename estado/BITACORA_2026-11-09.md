## Fix 3.1: Launcher Cycle Timeout — Monotonic Clock Fix
- **Archivo:** `sentinel_omega/launcher.py:495-506`
- **Problema:** `time.sleep(420)` usa CLOCK_REALTIME, vulnerable a saltos de reloj (NTP). Causaba timeouts falsos a los ~193s en lugar de 420s.
- **Fix:** Cambiado a `threading.Event.wait(420)` que usa CLOCK_MONOTÓNICO en Linux (inmune a ajustes de reloj).
- **Validación:** 
  - Ciclo #1: 136s completado sin timeout ✅
  - Ciclo #2: 151s completado sin timeout ✅
  - Heartbeat `cycle_end` escrito correctamente ✅
  - Watchdog "OK net+agent+heartbeat" cada 60s ✅
- **Resultado:** ✅ PASS

## Fix 3.2: Alfa-2 Thread Timeout 60s → 180s
- **Archivo:** `sentinel_omega/infrastructure/pipeline/layer_runners.py:914-936`
- **Problema:** Alfa-2 hace 6-9 llamadas API secuenciales a Copernicus (S1/S2/S3 × 3 zonas), cada una 15-20s → total 90-180s. Timeout de 60s era insuficiente.
- **Fix:** `alfa2_thread.join(timeout=180)` extendido a 180s (3 min).
- **Validación:** 
  - Alfa-2 completó 3 zonas en ~52s (ciclo #1) y ~62s (ciclo #2) ✅
  - "Alfa-2 pipeline: 3 zones analyzed" sin warnings de timeout ✅
